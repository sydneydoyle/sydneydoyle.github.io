Catching unannounced product changes

Built a weekly AI workflow that connects product changes to documentation gaps and customer-facing guidance.

Challenge: Hightouch ships quickly, and changes do not always come with an announcement. Documentation and support teams need to know what changed, which customers may be affected, and what guidance needs updating.

Connecting changes to customer context

I built a scheduled workflow that reviews GitHub, LaunchDarkly, Pylon, our analytics warehouse, and product channels where Product and Engineering share updates. It connects code changes with rollout information, customer questions, and account context, then produces weekly Slack briefs tailored to Docs and customer-facing teams.

The Docs brief identifies stale or missing guidance and suggests edits. The customer-facing brief explains changed behavior, potential customer questions, and troubleshooting guidance, with links back to relevant sources. Team members can flag useful items, noise, and documentation gaps.

From a product change to action

One weekly report surfaced a change to HubSpot list syncs: matching began recognizing secondary email addresses and ignoring case. Rows that previously failed could now sync successfully.

Customer-facing guidance

The brief explained the behavior change, anticipated questions about growing lists, and supplied troubleshooting context and source references.

Documentation gap

The workflow flagged an existing error entry whose explanation had become misleading, giving Docs a specific section to review and update.

When a change needs confirmation

Each Docs finding identifies the page or section, explains what changed, links to the evidence, and suggests an edit or a question for the owner. For example, the report found that several destination guides only told readers to select an audience from a dropdown. It pointed to the change that added another option and suggested updating those steps to say readers can also enter an audience ID.

Another finding flagged a missing guide for an integration whose code had merged. Customer availability was still unclear, so the brief gave Docs a specific question for the owner: is the integration available, and should we publish the guide?

Result and iteration

The workflow runs weekly, and I have already used its findings to identify documentation gaps. One Docs brief flagged 11 proposed fixes, including the HubSpot entry and a destination rename. I continue to refine the workflow and its output as teams use it.
